# rCodex 自研网关 v0.2 设计

## 目标

v0.2 的目标是把自研网关从“能建立会话并流式回答”推进到“重启后仍能继续工作、模型可调整、文件可带入、用量可观察”。费用限制组件不属于网关能力，已从仓库移除。

## 交付范围

### 1. 会话恢复

- `sessions.json` 保存 Codex `threadId`、工作目录、权限模式、模型和最近状态。
- 网关启动后调用 `thread/resume` 恢复 `starting` / `running` / `waiting-approval` 会话。
- 手工恢复接口：`POST /sessions/:id/resume`。
- 恢复成功将 `resumeStatus` 置为 `resumed`；失败会把会话标记为 `failed` 并保留原因。
- 已完成或失败会话不自动恢复，避免重复执行轮次。

### 2. 运行时模型配置

- 接口：`PUT /sessions/:id/runtime-config`。
- 请求支持 `model`、`reasoningEffort`、可选 `serviceTier`。
- 先调用 app-server 的 `thread/settings/update`，成功后再写入会话，避免本地状态与后端状态分叉。
- 下一轮自动使用保存的模型和推理强度。

### 2.1 会话级 Provider

- `CODEX_MODEL_PROVIDERS` 以 JSON 声明可选 Provider 及其模型；API 不暴露任何密钥。
- 创建会话时传 `modelProvider` 和 `model`，网关在 `thread/start` 中同时透传。
- Provider 持久化在会话中，并在 `thread/resume` 中原样恢复。
- Provider 绑定在 thread 上；运行时配置接口拒绝跨 Provider 切换（409），跨 Provider 请创建新会话。

### 3. 附件

- 接口：`POST /sessions/:id/attachments`，当前接收 JSON + base64，单文件上限 10 MiB、每个会话最多 20 个。
- 文件名只保留安全字符，文件写入工作区 `.rcodex/attachments/<sessionId>/`，权限为 `0700/0600`。
- 接口：`GET /sessions/:id/attachments` 查看会话附件。
- 追加轮次时通过 `attachmentIds` 选择附件；图片以 `local_image` 输入块发送，文本文件以受限长度的文本块发送。
- 附件路径始终经过允许根目录校验，不接受客户端直接指定任意路径。

### 4. Token 用量

- 消费 app-server 的 `thread/tokenUsage/updated` 通知。
- 用量写入会话的 `usage` 字段，并广播 `session-usage` 事件。
- 汇总接口：`GET /usage`，返回按会话明细和全局累计值。

## 非目标

- v0.2 不复制闭源 Gateway 的完整控制台、通知插件、定时任务或 Provider 管理。
- v0.2 不在网关内实现价格计算、余额限制或请求拒绝组件。
- 附件暂不支持浏览器 multipart；保留 JSON base64 作为无第三方依赖的兼容方案，后续可增加 multipart 适配层。

## 安全与故障策略

- 任何附件写入失败、越界路径或无效 base64 都拒绝请求。
- `thread/settings/update` 失败时不更新本地配置。
- `thread/resume` 失败只影响对应会话，不阻止整个网关启动。
- 用量字段只接受数值型累计，异常事件不会导致请求失败。

## v0.3 候选

1. 真正的历史事件持久化与分页，而不是只保留进程内环形缓冲。
2. multipart 上传、下载和图片 inline 预览。
3. 与官方 App 的接口回归矩阵，以及自研/闭源双实现兼容性测试。
4. 通知渠道的最小可插拔接口，以及定时任务 cron / 投递 / 重试增强。
